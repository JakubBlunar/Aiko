## Repeated, underspecified forward questions

The forward-curiosity producer retained a topic in its pool payload but rendered
only a model-drafted question. A vague draft therefore lost its referent. The
wants feeder independently copied historical journal questions, and initiative
could repeatedly deliver them without claiming the owning pool cue. Its lexical
acted-on test could miss an otherwise relevant answer to the vague wording.

Forward cues now retain the original activity, source timestamp and topic in the
rendered context. The handling section requires a specific question and one
clarification when the source itself is vague. Wants read available pool rows,
including migration of old journal references, and claim the same cue through
the final-prompt staging contract. Alternative delivery routes carry their cue's
handling as a budgeted bundle. Awaiting, resolved, expired and delayed questions
cannot survive in an independent wants list. Forward questions have one verified
ask; an unrelated response is not recorded as successful fulfillment.

Validation includes isolated producer/wants/final-prompt/ask/answer chains,
omission without consumption, unrelated replies, legacy references and ordinary
cue/initiative/handling regressions. These checks establish the delivery contract,
not guaranteed model adherence on every live turn. Backend restart is needed.

## 1. Model-output contracts

An isolated synthetic probe on the configured Venice chat route reproduced the
second-thought failure: all 160 completion tokens were hidden reasoning, with
zero visible characters and a length stop. Disabling reasoning on that call
produced a valid two-field draft using 80 visible tokens. Second thought now
overrides effort only for this provider, retaining the configured output cap,
cache affinity and other providers' effort settings. Truncated drafts are never
queued, even when partial fields parse; content-free output metrics distinguish
truncation from malformed text and legitimate NONE declines.

Situation extraction keeps rejecting unknown citations. Feedback on the next
already-scheduled call now covers the observed nested evidence_id and
evidence_shape reasons as well as top-level IDs and missing user evidence. No
extra inference retry or guessed replacement citation is introduced.
